# 결정 기록 (ADR)

여러 곳에 걸친 결정의 이유, 버린 대안, 결정 시점을 남긴다. ADR은 현재 규칙의 정본이 아니다.
지금 무엇이 규칙인지는 `AGENTS.md`와 `docs/architecture/`가 맡고, ADR은 그 규칙을 왜 그때 그렇게
정했는지를 기록한다. 맡는 사람이 졸업으로 바뀌어도 다음 사람이 "왜?"의 답을 찾게 하는 것이
목적이다.

## 기록 위치

| 위치                    | 담는 내용                            | 판별 질문                                          |
| ----------------------- | ------------------------------------ | -------------------------------------------------- |
| 코드 주석               | 한 모듈·함수 안에서만 의미 있는 이유 | 이 코드가 사라지면 이유도 함께 사라지는가?         |
| `AGENTS.md`(루트, 폴더) | 지켜야 할 규칙                       | 이 부분을 고치는 사람이 꼭 알아야 하는가?          |
| `docs/architecture/`    | 복잡한 로직이 지금 동작하는 방식     | 코드만 읽어서는 흐름을 알기 어려운가?              |
| ADR                     | 여러 곳에 걸친 결정의 이유·대안·시점 | 왜 다른 안을 버렸고 언제 바뀌었는지 추적해야 하나? |

위에서부터 차례로 판별한다. 결정이 현재 규칙을 바꾸면 규칙 문서를 먼저 고치고, 아래 기준을
채울 때만 ADR을 더한다.

## 기록 기준

다음 세 가지가 모두 참일 때만 ADR을 쓴다.

1. **되돌리기 어렵다**: 나중에 마음을 바꾸는 비용이 크다.
2. **맥락 없이는 의아하다**: 다음 사람이 코드나 문서를 보고 "왜 이렇게 했지?"라고 묻게 된다.
3. **실제 trade-off의 결과다**: 진짜 대안이 있었고 구체적인 이유로 하나를 골랐다.

하나라도 빠지면 쓰지 않는다.

## 중복 방지

- 규칙 문서에는 결론과 함께 `근거: ADR-NNNN` 링크 한 줄만 둔다. ADR에 현재 규칙 전체를 복사하지
  않는다.
- 같은 결정을 코드 주석, 규칙 문서, ADR 세 곳에 모두 설명하지 않는다.

## 작성 규칙

- 사용자가 기록을 승인할 때만 만든다.
- 파일명은 `NNNN-영문-kebab-case.md`다. 번호는 가장 큰 번호에 1을 더한다. 번호는 재사용하지
  않는다.
- 새 ADR은 아래 목록에 더한다.
- 채택한 ADR의 본문은 고치지 않는다. 오타, 깨진 링크, 상태 줄만 고친다. 결정이 바뀌면 새 ADR을
  쓰고 이전 ADR의 상태를 `ADR-NNNN으로 대체`로 바꾼다.

### 템플릿

```md
# 결정의 짧은 제목

**상태**: 채택 · **날짜**: YYYY-MM-DD

맥락, 결정, 이유를 1~3문장으로 쓴다.
```

한 문단이어도 된다. 다음 절은 필요할 때만 더한다.

- **검토한 대안**: 버린 이유가 자명하지 않아 다시 제안될 수 있을 때
- **영향**: 자명하지 않은 후속 영향을 알려야 할 때

상태는 `제안`, `채택`, `폐기`, `ADR-NNNN으로 대체` 중 하나다.
